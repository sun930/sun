## 1. Application.dataPath 工程路径

```csharp
   print(Application.dataPath);
```
- ✅ 可用时机：**仅编辑器模式**
- ❗ 发布游戏之后该路径不存在，**打包后不能用**
- 用途：编辑器拓展脚本获取工程 Assets 目录
- 示例输出：`xxx/Assets`

## 2. Resources 资源文件夹
>需要手动创建文件夹 `Assets/Resources`
```csharp
// 拼接路径（仅编辑器有效，打包后不要这么写） 
print(Application.dataPath + "/Resources");
```
### 核心要点

1. 动态加载资源放这里，使用 `Resources.Load()` API 加载
2. **文件夹内全部内容都会被打进游戏包**
3. Unity 打包会对资源做**压缩加密**
4. 📌打包之后：**只读**，不能直接 IO 读写文件，只能用 Resources 接口加载
5. 不要放没用资源，会增大包体

> ⚠️ 不建议直接拼接字符串拿物理路径，打包后路径失效，统一用 Resources 加载接口

## 3. StreamingAssets 流动资源文件夹
>手动创建：`Assets/StreamingAssets`

```csharp
print(Application.streamingAssetsPath);
```
### 核心要点

1. 打包**不会压缩、不会加密**，原始文件保留
2. 权限
    - PC 端：✅可读✅可写
    - Android/iOS 移动端：✅只读 ❌不能写入
3. 使用场景：放原始配置文件、初始资源，程序运行读取原始文件
4. 移动端不能用 File 直接写入，只能读

## 4. persistentDataPath 持久数据文件夹
```csharp
print(Application.persistentDataPath);
```
### 核心要点

1. **无需手动创建**，运行时平台自动生成
2. ✅**全平台：可读、可写**（PC、安卓、苹果都可以读写）
3. 用途
    - 动态下载的文件
    - 游戏运行时生成、修改保存的数据（存档、配置、下载资源）
4. 📌游戏运行需要写入文件，优先选这个文件夹！


## 5. Plugins 插件文件夹
>手动创建 `Assets/Plugins`

- 一般不获取物理路径
- 存放各平台原生插件：Android `.so`、iOS 库文件、原生 dll
- 平台相关底层交互文件放这里

## 6. Editor 编辑器文件夹
>手动创建 `Assets/Editor`

```csharp
//仅编辑器模式有效 
print(Application.dataPath + "/Editor");
```
### 核心要点

1. 存放**编辑器拓展脚本**（自定义窗口、菜单工具）
2. ✨**该文件夹内所有内容不会打包进游戏**
3. 只有在 Unity 编辑器环境才会执行里面代码

> 业务逻辑游戏运行脚本不要放这里，发布后直接失效

## 7. Standard Assets 默认资源文件夹
>手动创建 `Assets/Standard Assets`

- Unity 旧版自带资源存放目录
- **文件夹内脚本优先编译**，编译顺序优先级高
- 现在新项目很少使用
