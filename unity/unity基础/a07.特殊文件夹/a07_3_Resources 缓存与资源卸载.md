## Resources 重复加载资源，会不会浪费内存？
- Resources 加载资源后，**资源会缓存在内存当中**
- 再次加载同一个路径资源：不会重新从硬盘读取，直接拿内存里的缓存
- ✅结论：**重复加载不会造成多份内存，不会内存浪费**
- ⚠️但是依然有**性能开销**：内部要做查找缓存的逻辑，不要无意义频繁重复加载

>内存只存一份，多次 Load 拿到的是同一个资源对象的引用。

## 手动释放缓存资源的两种方式
### 方式 1：`Resources.UnloadAsset(资源对象)` 卸载指定资源

```csharp
Resources.UnloadAsset(tex);
tex = null;
```
重要限制：
1. **不能卸载 GameObject、预制体对象**，哪怕没有实例化出来也不行
2. 适用：图片 Texture、音效 AudioClip、文本、材质等**不需要实例化的资源**
3. 使用完建议手动把引用置`null`：`tex = null;`，避免野引用

> 开发中单独用这个方法的场景比较少。

### 方式 2：`Resources.UnloadUnusedAssets()` 卸载**未被使用**的全部资源

```csharp
Resources.UnloadUnusedAssets();
GC.Collect(); //强制C#垃圾回收
```
- “未被使用”：**没有任何 C# 变量持有这个资源的引用**
- 典型使用时机：**切换场景的时候调用**
- 配合`GC.Collect()`，把 C# 层的垃圾一并回收
- 内部是异步执行，不是立刻全部释放

重点：如果你脚本还有变量保存着资源引用，`UnloadUnusedAssets()`**不会卸载这个资源**！ 想要它被卸载：必须先把所有引用赋值为`null`。
