新开一个协程是在原线程之上开后进行逻辑分时分步执行
![[assets/Pasted image 20260914182431.png]]
如果要开启一个协程，其实是在当前我们执行这个开启协程逻辑去开启的，开启协程过后，这个协程里面可以把代码分成几步执行。比如说箭头处开启一个协程函数，我们可以通过特殊的写法，把这个函数明明是需要重上到下一次执行完毕的。我们可以把函数变成几部分。当执行这个函数的时候，先执行1部分，执行完之后。不在往下执行。会根据第一部分返回内容决定得到什么时候在执行，这个时候就会把这个协程程序处于一个挂起状态，然后主程序继续往下跑逻辑，回到下一帧的时候，判断这个函数没有执行完，返回的这个内容条件满不满足，如果满足会继续执行第二部分，也就是说，这个协程函数里面每一个步骤的执行至少等一帧才会执行，具体等多久执行根据返回的内容来决定的，协程就是把一个函数分成n步执行，n步我们可以控制，每一步的等到时间等待多久执行下一步也是可以控制的。

## 一、Unity 是否支持多线程

1. Unity**支持多线程**，可以自己 new Thread 开启子线程
2. ⚠️重要限制：**子线程不能访问 Unity 对象 / 组件相关 API**（transform、GameObject、GetComponent 等）
3. 子线程与主线程数据交互方案：**公共内存容器（队列 Queue）**，子线程写数据，主线程 Update 读数据
4. 注意：线程用完必须关闭，防止内存泄漏
```csharp
private Thread t;
private Queue<Vector3> queue = new Queue<Vector3>();

void Start()
{
    t = new Thread(Test);
    // t.Start();
}

private void Test()
{
    while (true)
    {
        Thread.Sleep(1000);
        System.Random r = new System.Random();
        // 子线程只往队列写入数据，不操作Unity对象
        queue.Enqueue(new Vector3(r.Next(-10,10), r.Next(-10, 10), r.Next(-10, 10)));
    }
}

void Update()
{
    // 主线程Update读取队列，操作transform
    if ( queue.Count > 0 )
    {
        this.transform.position = queue.Dequeue();
    }
}

private void OnDisable()
{
    // 销毁时终止线程
    t.Abort();
    t = null;
}

//注意：Queue 多线程读写会有线程安全问题，本案例仅演示思路，实际项目需要加锁。
```

## 二、协程是什么

协程（协同程序）：**假多线程，不是真正操作系统线程**

- 本质：在**主线程内部**，把代码分时分步执行，避免主线程卡顿
- 作用：把耗时代码拆分，不阻塞游戏主循环
- 常用场景
    - 异步加载文件
    - 异步网络下载
    - 场景异步加载
    - 批量实例化防止帧卡顿


协程 vs 原生线程

|              | 原生 Thread 线程                | 协程 IEnumerator     |
| ------------ | --------------------------- | ------------------ |
| 执行方式         | 操作系统并行管道，和主线程真正并发           | 跑在主线程内，分时分步执行      |
| 访问 Unity API | ❌ 不能操作 GameObject/transform | ✅ 完全可以使用 Unity API |
| 开销           | 开销较大                        | 开销小                |

## 四、yield return 各个返回值含义

> 执行时机参考：`Update → 协程(yield null/秒数) → LateUpdate → WaitForEndOfFrame → 渲染`

1. `yield return null;` / `yield return 数字;`
    - 等到**下一帧**，在 Update 和 LateUpdate 之间执行后续代码
2. `yield return new WaitForSeconds(秒);`
    - 等待指定秒数，再继续执行；Update 与 LateUpdate 之间
3. `yield return new WaitForFixedUpdate();`
    - 等待下一次物理帧，在 FixedUpdate、碰撞检测之后执行
4. `yield return new WaitForEndOfFrame();`
    - 等 LateUpdate、摄像机、GUI 渲染全部完成之后执行；常用于截图
5. 异步加载对象（资源 / 场景异步操作返回值）
    - 等待异步操作完成，后面课程详解
6. `yield break;`
    - **直接终止协程**，后续代码不再运行

## 五、协程受物体 / 组件激活销毁的影响

1. **游戏物体销毁**：协程直接停止
2. **游戏物体失活 SetActive (false)**：协程停止
3. **组件失活 this.enabled = false**：✅协程**仍然继续运行**

> 重点坑点：脚本组件关掉，协程还跑；物体隐藏销毁协程就停。

## 易错点总结

1. ❌不要直接调用协程函数 `MyCoroutine()`，必须用 `StartCoroutine()`
2. ❌子线程不能操作 Unity 对象 API，只能用队列等容器做数据中转
3. ❌`yield break`会直接结束协程，写在前面会截断后面逻辑
4. ⚠️多线程读写 Queue 存在线程安全，正式项目需要 lock 锁
5. ⚠️线程一定要记得 Abort 释放，协程注意物体失活销毁逻辑
