## 1. 同步场景加载 `LoadScene()`

```csharp
SceneManager.LoadScene("Lesson20Test");
```
### 同步加载缺点

切换场景时 Unity 会销毁当前场景全部对象，再加载新场景资源。 如果场景资源量大，**主线程阻塞，游戏直接卡顿**。

> 异步加载就是用来解决卡顿问题。

## 2. 异步场景加载两种方式
返回值：`AsyncOperation` 异步操作对象
### 方式 1：事件回调 `completed`
```csharp
AsyncOperation ao = SceneManager.LoadSceneAsync("Lesson20Test");
ao.completed += (a) =>
{
    print("场景加载结束");
};
```
- `completed`：场景全部加载激活完成后自动回调
- 优点：不用协程
- 注意：注册事件忘记`-=`会产生内存泄漏

### 方式 2：协程异步加载
致命坑：加载新场景，旧场景物体默认全部销毁。 如果协程脚本所在物体被销毁，**协程直接被 Unity 停止，后续逻辑不会执行！**
解决方案：给这个物体设置过场景不销毁
```csharp
DontDestroyOnLoad(this.gameObject);
StartCoroutine(LoadScene("Lesson20Test"));
```
协程方法完整逻辑
```csharp
IEnumerator LoadScene(string name)
{
    //开启后台异步加载场景，不卡主线程
    AsyncOperation ao = SceneManager.LoadSceneAsync(name);

    print("异步加载过程中 打印的信息");

    //写法A：直接yield return ao;
    //Unity协程协调器识别AsyncOperation，自动等待场景加载激活完成，再向下执行
    yield return ao;
    
    print("异步加载结束后 打印的信息");
}
```
## <font color="#4bacc6">为什么事件回调**不会出现协程那种「对象销毁后逻辑执行不了」的问题？**</font>

协程是挂载在`MonoBehaviour`对象上的。如果物体`Destroy`，该物体上所有协程会**立刻被 Unity 引擎停止**，剩下代码不再跑。

而 C# 事件（委托）保存的是**函数引用**：
1. 事件内部存储的是方法的委托引用，不是依赖 Mono 对象的生命周期。
2. 当你把某个脚本的方法注册进事件，委托会持有这个脚本对象的引用。
3. 哪怕这个物体从场景中删除（`Destroy(gameObject)`）：
    - 场景里的物体实例标记为待销毁；
    - 但是**事件委托还持有该对象引用**；
    - GC 垃圾回收判定：对象仍然被引用，**不会被回收**。
4. 只要事件被触发，保存的函数引用依旧可以正常执行里面的逻辑。
   
坑点：内存泄漏！ 如果你忘记**取消事件注册 (-=)**，委托会一直持有对象引用，被 Destroy 的物体永远无法 GC 释放，造成内存泄漏。
