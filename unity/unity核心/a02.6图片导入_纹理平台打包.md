## 平台设置主要设置什么?
平台设置主要设置纹理最终打包时在不同平台的尺寸、格式、压缩方式
它非常的重要，因为它影响了你的包大小和读取性能方面的问题
## 参数相关
![[assets/Pasted image 20261104233931.png|315]]
- MaxSize:设置导入的纹理的最大尺寸，即使美术出的很大的图，也可以通过这里把它们限制在一定范围内
- Resize Algorithm:当纹理尺寸大于指定的Max Size时，使用的缩小算法
  - Mitchell:默认米切尔算法来调整大小，该算法是常用的尺寸缩小算法
  - Bilinear:使用双线性插值来调整大小。如果细节很重要的图片，可以使用它，它比米切尔算法保留的细节更多
- <font color="#ff0000">Format:纹理格式</font>,  各平台支持的格式有所不同,  如果选择Automatic,  会根据平台使用默认设置

- 关于格式选择的注意事项根据不同平台单独进行设置
   - IOS：旧版本依靠 PVRTC 获取广泛兼容性；**Unity6 不再支持 PVRTC**。 项目最低设备版本锁定 A8（iPhone 6 及以后），优先选择 ASTC 格式；ASTC 支持多种块大小，画质、灵活性更好。 如果需要兼容老旧 A7 芯片设备，可以选用 ETC2。
   - Android
     安卓设备碎片化严重，GPU 图形标准差异大，一般按图形 API、压缩格式产出多个安装包：
     1. 面向 OpenGL ES 3.0 / Vulkan 的安装包：支持 ETC2、ASTC，优先 ASTC；
     2. 面向 OpenGL ES 2.0 的老设备安装包：仅支持 ETC1；ETC1 没有原生 Alpha 通道，带透明的贴图需要开启图集的 Split Alpha Channel 拆分 Alpha 通道。 补充：如果设备不支持选定的硬件压缩格式，贴图会在运行时解压，显存暴涨、容易卡顿，需要配置 fallback 回退方案。 打包步骤：
     3. 构建 OpenGL ES 3 / Vulkan 目标 APK 
        1-1 打开 Android Player Settings（Edit > Project Settings > Player，选择 Android） 
        1-2 找到 Graphics APIs 
        1-3 移除 OpenGL ES 2 
        1-4 Build Settings 打包 APK
     4. 构建 OpenGL ES 2 单独 APK（仅用来兼容极老机型，新项目一般很少做） 
        2-1 打开 Android Player Settings 
        2-2 找到 Graphics APIs 
        2-3 只保留 OpenGL ES 2，移除 OpenGL ES 3、Vulkan 
        2-4 Build Settings 打包 APK

- Compression:选择纹理的压缩类型，帮助Unity正确选择压缩格式会根据平台和压缩格式的可用性进行压缩。
- Use Crunch Compression:启用后，使用Crunch压缩。Crunch是一种基于DXT或ETC纹理压缩的有损压缩格式。压缩时间长，解压速度快。
